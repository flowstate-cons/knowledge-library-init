# Agent and Skill Segmentation

**Function:** how to split work across agents and skills so each stays focused, reliable and safe: one role per agent, one capability per skill, and only the access each needs.

## Overview

As the agent team grows, the pull is to keep adding jobs to an agent that already works. This pattern keeps the team lean: each agent and each skill is scoped as tightly as its job allows, without splitting things so small they become hard to manage.

## Method

- **One role per agent.** An agent does one job: sales follow-up, or bookkeeping, or content, not a blend. A role can be broad (a content agent writing both posts and newsletters). "One role" means focused, not artificially small.
- **One capability per skill.** A skill covers one capability. If the same capability produces different outputs (a short email and a long proposal), keep them as options inside one skill rather than splitting it. A new skill is for a genuinely new capability.
- **Only the access each needs.** Connect an agent only to the tools it actually uses, read-only where possible. Anything that deletes or sends to other people sits behind a clearly named skill or an owner check.

## Rationale

- **Less noise.** A focused agent loads only what its job needs, so it works from a smaller, cleaner context.
- **Fewer mistakes.** Fewer tools and a narrower scope mean fewer ways to act on the wrong thing.
- **Easier to fix.** When something goes wrong, a focused agent or skill is easier to understand, test and correct.

## In Practice

- When a request spans two roles, hand it across two agents rather than widening one.
- Before creating a new agent, check the Agents folder: if an existing agent's scope already covers the job, extend its page instead.
- Catch over-scoping early: a skill attached to an agent that cannot use it well is removed, not left in place.

## Limitations

- A guide, not a law. A small business may reasonably run one agent across a few roles at first; split when the agent starts making mistakes or its instructions get long.
