# Rule Tiers

**Function:** how a rule is written and when it earns a place. Read before adding a rule to any page, skill or instruction.

## Tiers

Every rule is one of two kinds:
- **Law:** no exceptions. It holds in every case, and breaking it is a failure whatever the outcome.
- **Principle:** expected, with room. Departing from it with a stated reason is fine; departing without one is not.

On any page, Laws come before Principles.

## Test

If you can name an exception, it is a Principle, not a Law. A real Law is hard to find an exception to; one found in the first hour means it was never a Law.

## Admission

- A rule earns its place when a problem has happened at least twice, or when research clearly supports it. One incident is a preference, not a rule.
- A minor, occasional annoyance never becomes a rule. Judgment in the moment handles it better.
- New rules, and making an existing rule stricter, need the owner's approval. Removing or loosening a rule does not.
- Record a rule that was refused, with the reason, so it is not proposed again.

## Writing

- One rule per line, stated plainly.
- Keep the reason the rule exists. A rule without its reason handles only the cases it happens to name.
- Put the rule on the page it governs, not in a separate list that drifts away from it.

## Limits

A page with more than about 15 rules is a warning sign. Review the whole set: a list nobody can remember protects nothing.
