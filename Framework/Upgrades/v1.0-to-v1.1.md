# Upgrade Guide, v1.0 to v1.1

**Function:** move a library built from the v1.0 Knowledge Library template onto the v1.1 layout, without losing anything the owner has already written. Run by the library manager, once, telling the owner what changed afterward rather than asking step by step. Every move here is reversible through git history.

## Overview

v1.1 regroups the framework's own pages under `Framework/`, adds `Records/` for the library's history, moves `Operating Principles` into `Business/`, renames `Decisions` to `Key Decisions`, renames the three pillar hubs to end in Overview, splits Personal into Profile, Preferences and a Personal Overview hub, adds Working Philosophy, retires the per-source capture page, reshapes every hub page, moves Code of Conduct and Working Philosophy to their current shape, re-layers the Glossary, adds Page Standard and Tag Set, rebuilds `index.md`, renames Knowledge Library and Network to Knowledge Network, and updates the routing text in AGENTS.md and README.md. Nothing about Business, Personal or Agentic Layer's other content pages changes in kind, only in the path or shape of a handful of framework pages.

## Procedure

1. Read `CHANGELOG.md`'s 1.1 entry in full before starting, so every move below has a reason attached.
2. Create `Framework/Foundations/` and `Framework/Library/`. Move `Foundations/Core Philosophy.md`, `Code of Conduct.md`, `Rule Tiers.md`, `Glossary.md` and `Knowledge Library and Network.md` into `Framework/Foundations/`, renaming the last one `Knowledge Network.md` and its title to Knowledge Network as you move it. Move `Foundations/Knowledge Library Operating Manual.md` and `Library/Blueprints/` into `Framework/Library/`.
3. Move `Foundations/Operating Principles.md` to `Business/Operating Principles.md`, and add it to the business hub's Contents list.
4. Create `Records/`. Move `Library/log.md` to `Records/Log.md` and `Library/Ingest History.md` to `Records/Source History.md`. Reformat Source History's existing entries into the new one-line-per-source shape, giving the date, submitter, name, route in, status and an optional note, and add a link to each source's filed raw file. Keep anything that does not fit a single line in an Earlier Detail section at the bottom, verbatim.
5. Create `Records/Library Maintenance Queue.md` from the v1.1 template. It starts empty, so there is nothing to migrate.
6. Rename `Agentic Layer/Decisions/` to `Agentic Layer/Key Decisions/`, and its hub page to match, stating plainly that it holds the business's key decisions and not only decisions about the agents. Rename `Library/Blueprints/Decision Blueprint.md` to `Key Decision Blueprint.md`, and add Context, Alternatives and a Notes field to it. Existing decision pages keep their old section names, and are reshaped only if you are touching one anyway.
7. Rename the business hub to `Business Overview.md`, the Agentic Layer hub to `Agentic Layer Overview.md`, and the Personal hub to `Personal Overview.md`. Split the old Personal hub's Profile and Working Style sections into new `Personal/Profile.md` and `Personal/Preferences.md` pages, using the v1.1 blueprints for their shape, and rewrite the old hub into a short pointer to both plus Voice and Style. Add `Framework/Foundations/Working Philosophy.md` from the v1.1 template.
8. Retire the per-source capture page. Delete `Library/Sources/` and its hub. For any capture page already written, fold its summary into the matching Source History line, and into the source's own frontmatter if it can carry one, before deleting it. Update `Library/Blueprints/Source Blueprint.md` to the v1.1 version, which names raw frontmatter fields rather than a page.
9. Reshape every hub page in one pass, a mechanical rename safe to batch since it touches only headings. On each hub, fold its Scope section into Overview, rename Pages to Contents, and fold Limitations into a new Connections section that links the neighboring hub or the pages a reader most likely wants next, keeping any Notes section as it is.
10. Replace `Framework/Foundations/Code of Conduct.md` and `Working Philosophy.md` with the v1.1 template's content, keeping this library's own genuinely business-neutral additions worked into the new Conduct section rather than left behind.
11. Re-layer `Framework/Foundations/Glossary.md`, adding an AI And Agent Fundamentals section ahead of the library's own terms, and folding the old Agents and Rules sections into a single Library Terms section. Keep What Goes Where and any Business section as is.
12. Create `Framework/Library/Page Standard.md` and `Framework/Library/Tag Set.md` from the v1.1 templates. Move Blueprints' Starting A Page table onto Page Standard, and link both new pages from `index.md`'s Library section and from Blueprints' and the Operating Manual's Connections. Add a short, filled-in example to every blueprint, clearly marked for deletion.
13. Rebuild `index.md` as the v1.1 template's single page catalog, with a Routing block at the top, criticality-scaled entry length, and Raw excluded.
14. Update every link and path reference you find pointing at an old location, including AGENTS.md, index.md, any hub Contents list, and any page that names a moved or renamed file in prose, such as the old Knowledge Library and Network title. Search rather than guess, since a missed reference fails silently.
15. Replace `README.md` and `AGENTS.md` with the v1.1 versions' structure and wording, including the current routing text in both, keeping this library's own filled-in facts, such as the owner's name, the library manager's name, and the folder renames chosen at setup, rather than the template's placeholders.
16. Add `Framework/About.md`. Set Release Date to v1.1's release date, Initialization Date to whatever this library's original setup date was (check `Records/Log.md`'s earliest entry if it is not recorded elsewhere), and Last Updated to today. Add a line to its Upgrade History with the date of this upgrade and a link back to this guide.
17. Add a line to `Records/Log.md` with the date, that the library moved to Framework v1.1, and a link to this guide.

## Limitations

- This guide does not rename or restructure any Business or Agentic Layer content page the owner created beyond the hub renames and hub shape change named above. Those pages stay exactly as they are otherwise.
- If the owner renamed or merged any Foundations or Library folder during their own setup, adapt the move commands above to match. The destinations in v1.1 are fixed, and the sources are whatever this library actually has.
